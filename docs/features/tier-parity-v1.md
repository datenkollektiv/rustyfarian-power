# Feature: Tier parity v1

Adopts the tier-parity hardening contract from `rustyfarian-network` ADR-022 and `rustyfarian-ws2812` ADR-010 into this repo, as recorded in `docs/adr/003-tier-parity-contract.md`.

## Decisions
|                                                                                 Decision | Reason                                                                                     | Rejected Alternative                          |
|-----------------------------------------------------------------------------------------:|:-------------------------------------------------------------------------------------------|:----------------------------------------------|
|                                            Adopt the parity contract as an ADR, not code | The architecture already exists here; only the contract is missing                         | Immediate code enforcement                    |
|                                                                 Document-only first wave | Naming the contract needs buy-in before code                                               | Building the parity compile check this wave   |
|                                             Mirror the sibling naming (`tier-parity-v1`) | Keeps cross-repo feature docs findable by the same name                                    | A power-specific doc name                     |
|                                      Record sibling ADRs by reference, not re-litigation | The decisions were made and validated there                                                | Restating all sibling arguments in ADR-003    |
|                         State guarantees as observable outcomes, not identical internals | Identical internals would outlaw `BoundSleep`-style borrowing and valid timing differences | "Validate, block, and transition identically" |
| Classify capabilities: hardware limitation, unimplemented driver, behavioural difference | The missing esp-hal ADC/charging monitors are implementation gaps, not semantic divergence | One undifferentiated capability column        |
|                                             Enforce provider policy at link time as well | Duplicate or missing `critical-section` providers fail only at link (2026-10-29)           | Compile checks alone                          |
|                       Track enforcement as committed follow-ups with acceptance criteria | An accepted contract without completion conditions is unenforceable                        | Open-ended "potential" items                  |

## Constraints
- `stoker` stays `#![no_std]` with `critical-section` as its only dependency.
- No code changes in this wave.
- Platform pins stay: ESP-IDF v5.3.3 and esp-hal `=1.2.2` in lockstep with the sibling repos.
- Tracked files may name public `rustyfarian-*` repos.

## Adoption map
